# Контракт адаптера «МедАнгел»

Репозиторий реализует fail-closed anti-corruption layer. Имена endpoint и
полей ниже являются временным узким контрактом проекта, а не утверждением о
фактическом API «МедАнгела». Перед стендом их необходимо заменить по
Swagger/OpenAPI и обезличенным fixtures Заказчика.

## Разрешённая поверхность

Адаптер выполняет только `GET`:

- поиск услуг;
- список врачей по услуге и, при наличии, филиалу;
- свободные слоты по услуге, врачу и филиалу;
- health-check.

Вызовы создания, переноса и отмены записи отсутствуют в порте и адаптере.
`booking-link` выполняет повторную проверку текущего слота и формирует только
HTTPS URL домена `vodc.ru`.

Настраиваемые относительные paths:

- `MEDANGEL_SERVICES_PATH`;
- `MEDANGEL_DOCTORS_PATH`;
- `MEDANGEL_SLOTS_PATH`;
- `MEDANGEL_HEALTH_PATH`.

Абсолютный URL, protocol-relative path, query и fragment в этих настройках
отклоняются при старте. `MEDANGEL_API_URL` обязателен в production.

## Временный response mapping

Коллекция принимается непосредственно либо в поле `items`/`data`. Каждый
элемент обязан быть объектом. Текущие aliases:

| Внутренняя сущность | Обязательные поля | Допустимые aliases |
|---|---|---|
| Service | стабильный ID, название | `id/service_id`, `title/name` |
| Doctor | стабильный ID, имя | `id/doctor_id`, `title/name` |
| Slot | стабильный ID, время, doctor ID | `id/slot_id`, `starts_at/start` |

`service_id`, `doctor_id` и `branch_id` из ответа, если присутствуют,
обязаны совпадать с параметрами запроса. Время слота обязано содержать
timezone и нормализуется в `Europe/Moscow`. Противоречивые дубликаты,
неизвестный envelope, неверные типы и нарушение связей делают весь ответ
недоступным; частичные карточки из повреждённого ответа не показываются.

## Кеш и live validation

- справочники кешируются до `MIS_CATALOG_CACHE_SECONDS` (300 секунд);
- расписание — до `MIS_SLOTS_CACHE_SECONDS` (30 секунд);
- production использует общий Redis-кеш, development — ограниченный
  in-memory LRU;
- пользовательский query не появляется в ключе Redis: ключ содержит SHA-256;
- в value записываются только нормализованные разрешённые поля внутренних
  DTO, неизвестные поля и echo ответа отбрасываются до кеша;
- INFO/DEBUG-логи `httpx/httpcore` отключены, поскольку URL поиска содержит
  пользовательский query;
- параллельные одинаковые запросы внутри процесса объединяются;
- Redis-кеш является best-effort и не может сам отключить МИС.

Каждая карточка подписана и привязана к сессии. `validate_service`,
`validate_doctor` и `validate_slot` всегда обходят кеш. Перед redirect API
дополнительно требует, чтобы token совпадал с текущим выбранным слотом, и
проверяет цепочку `service → doctor → branch → slot` по свежему ответу.

## Ошибки и наблюдаемость

Timeout, network error, HTTP 429 и 5xx повторяются не более трёх раз с
коротким exponential backoff. Остальные 4xx и повреждённый JSON не
повторяются. Пользователь получает безопасный `mis_unavailable`, без
динамических данных. Ответ больше `MIS_MAX_RESPONSE_BYTES` (2 МБ по
умолчанию) прерывается до JSON mapping и не кешируется.

Метрики:

- `vodc_mis_requests_total{resource,result}`;
- `vodc_mis_cache_total{resource,result}`;
- `vodc_mis_request_duration_seconds{resource}`.

`VodcMisContractViolation` является critical: он означает schema drift либо
нарушение связей. До выяснения причин booking-воронка должна оставаться в
fallback.

## Обязательные contract fixtures стенда

1. Поиск и свежая повторная проверка услуги.
2. Врачи, отфильтрованные по услуге и филиалу.
3. Слоты с timezone и стабильной связью service/doctor/branch.
4. Исчезнувшая услуга, врач или уже занятый слот.
5. Timeout, 401/403, 429, 5xx, пустой и повреждённый JSON.
6. Pagination, если она присутствует в реальном API.
7. Точный authentication scheme и health endpoint.
8. Формат параметров штатной формы записи VODC.

Fixtures должны быть обезличены и получены от тестового стенда. Репозиторные
mock-тесты проверяют поведение границы, но не закрывают этот внешний gate.
