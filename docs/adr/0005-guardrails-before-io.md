# ADR-0005: Guardrails до внешнего I/O и пользовательского SSE

- Статус: принято
- Дата: 2026-07-29
- Уточняет: ADR-0002 и ADR-0004

## Контекст

System prompt не гарантирует соблюдение медицинских ограничений и grounding.
Потоковая модель может успеть отдать запрещённый текст до проверки полного
ответа. Разрешённое двухчасовое raw-хранение также не означает, что системе
нужно сохранять явно обнаруженные ПДн из запрещённого сценария.

## Решение

- нормализовать и проверять input до intent, сохранения и любого порта;
- не сохранять заблокированный raw-input даже в Redis;
- не давать LLM права выбирать инструменты или state transitions;
- передавать источники как данные и отклонять indirect injection при ingestion;
- буферизовать завершённые фрагменты модели и проверять накопленный ответ до
  каждого `text_delta`;
- при output violation завершать модельный поток и возвращать фиксированный
  fallback без опасного текста;
- писать только bounded guardrail kind/direction, без исходного содержимого.

## Последствия

- первый содержательный SSE-фрагмент может ждать завершения первого
  предложения;
- regex/policy-набор требует постоянного red-team расширения;
- ложноположительный результат приводит к безопасному отказу;
- Redis по-прежнему хранит разрешённый raw-диалог до двух часов, но не
  обнаруженные ПДн из заблокированных сообщений;
- ни одна модель и ни один benchmark не отменяют детерминированную проверку.
